# Деплой ЮртаНеЖди

## Коротко

```bash
git pull origin master
node build.mjs
# выложить на сервер СОДЕРЖИМОЕ папки dist/
```

Ветка в проекте одна — `master`. Никаких других веток на GitHub нет.

## Почему нельзя просто выложить репозиторий

В git лежат **исходники**, а не то, что отдаётся браузеру. Папка `dist/`
внесена в `.gitignore` и в репозитории отсутствует намеренно — её нужно
собирать у себя после каждого обновления.

`node build.mjs` не минифицирует и не транспилирует. Он делает одно: копирует
файлы, добавляя в имя хэш содержимого (`hero-demo.08d58b43.css`), и переписывает
ссылки в `index.html` и в import-ах модулей. Смысл — имя файла меняется вместе с
содержимым, поэтому браузер физически не может подсунуть старую версию.

Зависимостей нет, нужен только Node.

## Как проверить, что выложилась новая версия

Открыть исходный код страницы на сайте и посмотреть имена файлов. Они должны
совпадать с тем, что вывела сборка. Свериться можно так:

```bash
node build.mjs && ls dist/assets/css/ | grep hero-demo
```

Если на сайте имя файла другое — значит выложена старая сборка. Это самый
надёжный признак, потому что хэш считается от содержимого.

Быстрая проверка прямо в консоли браузера на сайте:

```js
[...document.querySelectorAll('link[rel=stylesheet]')].map(l => l.getAttribute('href'))
```

Ещё один признак: заголовок `Last-Modified` у `index.html` должен быть свежим.

## Заголовки кэширования (nginx)

- хэшированные файлы (`assets/**` с хэшем в имени) — можно `Cache-Control: immutable`,
  они никогда не меняются под тем же именем;
- `index.html` — обязательно `Cache-Control: no-cache`.

Сейчас на `index.html` заголовок кэширования не отдаётся вовсе, поэтому браузер
может держать его по своей эвристике и не показывать обновление. Это стоит
поправить — иначе даже правильно выложенная сборка доедет до пользователя не сразу.

## Частая ошибка

Выложить `dist/`, собранную раньше, без повторного `node build.mjs` после
`git pull`. Внешне всё выглядит обновлённым (файлы на месте, сайт работает), но
это старая версия. Проверяется по именам файлов — см. выше.
