# Visitka — контекст проекта

Этот файл — первая точка входа в новый чат по проекту. Здесь зафиксировано, что мы строим,
какая версия сейчас главная и какие правила нельзя потерять.

Дата обновления: 2026-08-21  
Текущий локальный preview: [desktop v20260821-4](http://127.0.0.1:4181/index.html?v=20260821-4#desktop-director)

## Куда идём

ЮртаНеЖди продаёт владельцу заведения не отдельное электронное меню, а один Mini App в
Telegram и MAX: гость открывает меню по QR, кассир принимает заказ, кухня готовит, директор
управляет точкой и видит результат. Главный коммерческий фокус сайта — владелец или управляющий;
гостевой экран остаётся доказательством простоты продукта.

Сейчас основной рабочий поток — production desktop «Продукт в телефоне». Следующий проход должен
усиливать понятность продукта и конверсию, сохраняя телефон и реальные экраны главным визуальным
героем.

## Что сейчас считается главным

- Production desktop: `index.html` + `.desktop-site`.
- Desktop stylesheet: `assets/css/desktop-landing.css`.
- Реальные экраны: `assets/js/desktop-product-screens.js`.
- Desktop interactions: `assets/js/desktop-landing.js`.
- Legacy/mobile markup остаётся в `.legacy-site`; выше 900 px он скрыт.
- Утверждённые desktop и mobile baseline находятся в `qa/approved-mockups/` и immutable.
- Мобильную композицию не растягиваем из desktop и не редактируем без отдельного запроса.

## Текущая desktop-композиция

1. Hero: клиентское меню в главном телефоне, директорский экран рядом.
2. Journey: один заказ проходит через гостя, кассу, кухню и директора.
3. Role theatre: один бот переключается между четырьмя ролями.
4. Director: аналитика и операционное управление точкой.
5. Sync: директор меняет меню, гость сразу видит результат.
6. Ways: самовывоз, к столику и доставка с живыми мини-демо без pinned-перелистывания.
7. CTA: заявка на демонстрацию Mini App.

## Как продолжать работу

1. Прочитать этот файл, `product.md`, `desktop.md` и `qa.md`.
2. Проверить `git status` и не трогать чужие незавершённые изменения.
3. Для desktop поднимать preview из корня на порту 4181:
   `python -m http.server 4181 --bind 127.0.0.1`.
4. Проверять страницу в браузере на 1280, 1440 и 1920 CSS px; отдельно смотреть естественный скролл,
   роль гостя и director section.
5. После визуального прохода обновлять `qa.md` и этот файл, затем фиксировать отдельным локальным
   коммитом только относящиеся к задаче файлы.
