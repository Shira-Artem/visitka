# plan_mobile — довести мобильную версию до уровня десктопа

## Цель
Десктоп уже premium: закреплённые scroll-сцены (Story, Ways), фирменные градиентные иконки, spotlight+3D-tilt, прорисовка иконок при скролле. Задача — не «подрихтовать», а сделать так, чтобы мобильная версия ощущалась настолько же круто и дорого, просто на языке тач-интерфейса (без пина скролла, без hover-эффектов, но с собственными тактильными/анимационными акцентами того же уровня). База уже есть (mobile fallback без sticky-пина для Story/Ways, кастомные mobile-акты, демо в телефоне работает и на мобильном) — сейчас это доводка и премиализация, а не построение с нуля.

## Область
Проверяем и полируем весь сайт на 375–414px: шапка/бургер-меню, Hero, Story (все акты: hero → как это работает → checkout → касса → кухня → директор), Ways (3 карточки способов получения), финальный CTA, футер, фикс-кнопка `.mobile-cta`.

Не трогаем desktop-раскладку/логику (`@media (min-width:981px)` и sticky-пин истории) — только всё, что попадает в `@media (max-width:980px)` / `(max-width:620px)` / `(max-width:360px)` в `assets/css/sections.css`, `hero-demo.css`, и мобильные ветки в `assets/js/main.js`.

## Что нужно добавить сверх багов — премиализация под тач
Десктопная «крутость» держится на курсор-эффектах (spotlight, 3D-tilt, hover-подсветка) и синхронизированной со скроллом прорисовке. На тач это нужно переизобрести, а не просто выключить:
- Прорисовка/скролл-триггеры уже частично есть (stroke-dashoffset у иконок Ways) — распространить тот же приём на Story-акты, если там сейчас просто fade-up без «рисования» деталей.
- Тактильная реакция на тап (press-состояние: scale/тень при `:active`) там, где сейчас только `:hover`-эффекты, которые на телефоне не работают вообще — то есть кнопки/карточки могут ощущаться «мёртвыми» на тач.
- Проверить, не осталась ли где анимация, рассчитанная на курсор (spotlight/tilt), которая просто не показывается на мобильном, — таким местам нужна тач-альтернатива (например реакция на сам факт входа в вьюпорт вместо курсора), а не пустота.
- Пересмотреть тайминг scroll-reveal анимаций Story/Ways на мобильном — сейчас нет возможности проверить это в headless-превью (нет composited-рендера), нужна ручная проверка на реальном скролле/устройстве.

## План действий (по приоритету, без спешки — сначала согласовать)
1. **Фикс тап-таргетов** (пункты 1–3 backlog) — самое дёшево и заметно для UX, начать здесь.
2. **Тактильная обратная связь на тач** (press-states для карточек Ways/Story, кнопок демо) — здесь ощущается «премиальность» больше всего.
3. **Скролл-триггер прорисовки** для Story-актов по аналогии с Ways-иконками, если сейчас там просто fade.
4. **Производительность блюров** — замерить на реальном Android/iPhone среднего класса, при необходимости сократить количество одновременных `backdrop-filter`.
5. **Мелкая полировка**: размер текста role-switch, паритет пунктов мобильного меню, решение по `.btn--ghost` высоте.

## Как проверять
Через `preview_start` в этой сессии скриншоты недоступны (headless-браузер не композитит кадры), а `pointer:coarse` не эмулируется (тач не симулируется) — верификация статики (размеры/оверфлоу/DOM) через `javascript_tool` работает, но реальные анимации/тайминги и тач-специфичные media query нужно смотреть либо на настоящем телефоне, либо в обычном Chrome DevTools с открытой панелью устройства (Device Mode эмулирует touch и переключает `pointer:coarse`).

## Осторожно при верификации в headless-превью
В этой браузер-панели `document.hidden === true` и `IntersectionObserver` не срабатывает вовсе (проверено отдельным тестовым наблюдателем — 0 вызовов за 3 секунды) — это НЕ баг сайта, а свойство самой панели (она не композит кадры, см. ошибку `screenshot`). Таймеры, поставленные СРАЗУ при загрузке страницы, в этой панели иногда не запускаются вовремя; тот же код, перезапущенный вручную через `javascript_exec` уже после загрузки, отрабатывает корректно и по графику (проверено: полный круг гость→касса→кухня→директор→гость за ~21с). Финальную визуальную проверку анимаций/автоплея делать на реальном телефоне или в обычном Chrome.
